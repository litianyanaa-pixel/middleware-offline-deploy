# 测试环境问题记录（论文素材）

> 多机离线部署 E2E 测试期间遇到的全部环境/工具问题，按时间序整理。
> 每条含：现象 → 根因 → 处置 → 可复用结论。

## 1. 残留服务实例干扰测试（应用层）

- **现象**：页面预览 API 返回的字段与最新代码不符；测试时行为"时对时错"。
- **根因**：8766 端口残留旧版本打包服务进程，请求被路由到旧代码实例；本轮实际端口为 8765。
- **处置**：`netstat -ano | grep <port>` 定位 PID → `taskkill //F //PID` 清理后单实例重启。
- **结论**：**每次改码后测试前必须清理旧实例**。长驻服务的"灵异现象"优先怀疑进程版本不一致。

## 2. CDP（Chrome DevTools Protocol）自动化三个坑（工具层）

1. 页面 JS 包在 IIFE 内，`eval_js("gotoStep(2)")` 报函数未定义 → 改为模拟 DOM 点击 `.wtab[data-v]`。
2. `Page.captureScreenshot` 的 `clip` 对**内部滚动容器**截出空白 → 退化为 `scrollIntoView` + 整屏截图。
3. `onclick=closeDrawers` 会把 event 对象误传为 `instant` 参数 → 箭头函数包裹 `() => closeDrawers()`。

- **结论**：浏览器自动化不要直接调用页面内部函数，一切通过 DOM 事件驱动；截图前先处理滚动。

## 3. Git Bash 调用 Docker 的路径转换（工具层）

- **现象**：`docker exec mw3 ls /bundle` 报目录不存在；`-v E:\...:/bundle` 挂载偶发异常。
- **根因**：MSYS 路径转换把容器内绝对路径 `/bundle` 改写为 Windows 路径。
- **处置**：所有 docker 命令加 `MSYS_NO_PATHCONV=1` 前缀；含中文的 Windows 路径卷挂载实测正常。
- **结论**：Git Bash 下容器路径一律加 `MSYS_NO_PATHCONV=1`。

## 4. Docker Desktop VM 反复整体崩溃（平台层，>=5 次）

- **现象**：执行中所有容器同时 `Exited (255)`，引擎 pipe 消失；两次崩溃均发生在 GB 级 tar 流经 SSH 管道传输时。
- **根因**：Docker Desktop (WSL2 后端) 在高吞吐 I/O 下 VM 稳定性不足；事后手动复现同一步骤正常，排除脚本问题。
- **处置**：
  1. 节点侧 >300MB 镜像 tar 替换为等格式小代理 tar（真实大镜像流传输已在 redis 138MB×3 规模验证）；
  2. 每次崩溃后重启引擎 → `docker start` 恢复容器 → 幂等重跑（distribute.sh 幂等设计派上用场）。
- **结论**：容器化 E2E 中"基础设施不稳"与"被测代码缺陷"必须区分——**同一失败点手动复现正常即可归因为环境**；被测脚本幂等性是应对环境抖动的关键设计。

## 5. 沙箱安全策略拦截 wsl.exe（平台层）

- **现象**：引擎崩溃后无法重启，Docker Desktop 的 WSL 后端起不来；`docker info` 在 pipe 可用/不可用间抖动。
- **根因**：WorkBuddy 沙箱程序黑名单拦截 `wsl.exe`，Docker Desktop 拉起 WSL 发行版的子进程被杀。
- **处置**：用户在安全中心（命令安全 → 程序黑名单）移除 `wsl.exe`。
- **结论**：受管控环境下做容器测试，先确认虚拟化后端依赖（wsl/vmrun 等）未被策略拦截。

## 6. Docker Desktop 自毁 WSL 发行版（平台层，最严重）

- **现象**：多次硬崩溃后，backend 日志出现 `removing data from ...Docker\wsl` / `wslEngine: Destroying distros` / `WSL has no installed distributions`；`wsl --list` 确认发行版消失，引擎反复闪断无法稳定。
- **根因**：连续硬崩溃 + `wsl --shutdown` 后，Docker Desktop 走入"重置"路径销毁自身发行版，且**无法无人值守自动重装**（GUI 引导界面等待交互，backend 日志停滞）。
- **影响**：VM 内全部容器/镜像状态丢失（测试容器 mwn1-5、mw2~mw5、mwe2e/ossh 镜像、mwe2e 网络）。
- **处置**：GUI 交互完成重装；复现物料全部落在宿主机 E: 盘（bundles/、dockerenv/、场景 json），**10 分钟内可完整重建测试矩阵**。
- **结论**：①容器内不存放唯一状态，一切可从宿主机产物重建；②硬崩溃后慎用 `wsl --shutdown`，可能触发 Docker Desktop 自毁重建；③测试环境"基础设施即代码"（Dockerfile/配置/脚本全部入库）使环境损失降为分钟级。

## 7. Git Bash cygheap fork 失败（工具层）

- **现象**：长会话后期本地命令间歇报 `child_copy: cygheap read copy failed ... fork: retry: Resource temporarily unavailable`，命令输出丢失。
- **根因**：Windows Git Bash (MSYS2) 在长会话/高进程数下 fork 复制失败的老问题。
- **处置**：重试即可；重要输出**落盘到文件**（如 deploy 输出写 `/bundle/deploy_run.log` 再读文件），不依赖 stdout 存活。
- **结论**：长测试流程中 stdout 是易失的，日志落盘才是可靠观测手段。

## 8. 综合方法论沉淀

1. **原子执行**：环境准备（垫片安装等）与被测动作合并为单次 `docker exec`，幂等可重放，避免中间状态被引擎崩溃打断。
2. **垫片分层**：伪 docker 需区分调用语义（`inspect` 查镜像架构→`amd64`、查容器健康→`healthy`、`compose ps`→表格），否则上游校验逻辑被误触发（镜像架构校验曾因垫片返回 `healthy` 而误报架构不符）。
3. **静态核验兜底**：运行时受阻时，解包产物本地 `bash -n` + grep 交叉引用核验可覆盖大部分断言（S6 组合场景即以静态核验完成）。
4. **失败分类学**：产品 bug / 测试代码 bug / 环境问题三类必须严格区分，避免"环境背锅"或"误改产品代码"（本轮两类都出现过：S4 POST_SQL 双重转义是真 bug，VM 崩溃是环境）。
